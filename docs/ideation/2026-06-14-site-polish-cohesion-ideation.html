A more polished, cohesive site

Seven surface-and-system moves to make Home Bartender feel like one finished cookbook, not a stack of similar pages.

Grounding context

The site already has a real, documented identity (docs/design/direction.md): warm editorial, light-only, Fraunces display + Newsreader body, cream surfaces (#F5F0E8) + terracotta accent (#9C3F2A), dark header chrome (#1A1810), full Tailwind v4 token set, reduced-motion handled. It is cohesive in intent — the gaps are execution: finished work that isn't wired up, edges that fall back to browser defaults, and per-page styling that drifts because it's copy-pasted instead of componentized.

Concrete gaps found in the code

  • Search is dead code. Search.astro is fully built & theme-styled but imported into zero pages/layouts — search effectively doesn't exist on the live site.
  • Related links show mangled slugs. RecipeLayout.astro:154 renders slug.replace(/-/g,' ') → "old fashioned" next to the page's own "Old Fashioned"; breaks "Naked & Famous", "Penicillin No. 2".
  • Nothing shareable. Only twitter:card=summary; no og:image, no schema.org Recipe JSON-LD — links unfurl as bare text, no Google rich results.
  • Edges fall back to defaults. No 404.astro; empty states only on home; print CSS only hides icons (the full spec in direction.md is unimplemented).
  • Drift by copy-paste. Eyebrow styling hand-applied across ~8 files; BASE_URL.replace(/\/$/,'') duplicated in ~13 files; .recipe-grid duplicated; 7–8 near-identical /by-* index templates.

Ranked survivors

1

Wire up the orphaned Pagefind search

Browse & discoveryConfidence 95%Complexity Low

A finished, on-brand component renders nowhere. Mount <Search mode="compact"/> in BaseLayout's header (an icon button in the dark chrome that expands to a Pagefind overlay, optionally a / or ⌘K shortcut), and mode="full" on a /search route. It already self-degrades when the index isn't built.

basis · direct: Search.astro exists, themed, dual-mode — grepped as imported only by inbox.astro, never BaseLayout.

Why it matters: the single highest polish-per-effort move on the list — a recipe collection with no search forces the filter bar for every lookup and can't answer freeform/ingredient queries Pagefind already indexes. Loudest possible "unfinished" signal, nearly free to fix.

2

Resolve related[] to real titles (then render as mini cards)

Browse & discoveryConfidence 95%Complexity Low

Build a slug→title map from the content collection at build time and render the actual title instead of the lowercased slug. The validator already guarantees every related[] slug resolves, so the lookup is total — no missing-key branch. Optionally upgrade related links from bare <li><a> to the same RecipeCard treatment for cross-surface consistency.

basis · direct: RecipeLayout.astro:154; titles live in frontmatter, free via getCollection('recipes').

Why it matters: casing mismatch is exactly the "quiet failure" that makes a careful editorial site read as unfinished — and it currently breaks any title with internal caps or punctuation.

3

Branded 404 + one shared empty-state family

Robustness & edge polishConfidence 88%Complexity Low

One EmptyState.astro (empty-coupe icon + message + "browse by spirit" links + the search box) reused for: zero-result filter views, empty /by-* facets, empty inbox, and src/pages/404.astro. A 404 is just an empty state that admits the URL was wrong — and 404s aren't hypothetical here: the inbox→category publish flow renames slugs by design, so promoted recipes generate dead inbound links.

basis · direct: no 404.* in src/pages; empty states only on home; faceted pages can legitimately render zero matches.

Why it matters: polish is judged at the edges — one shared component means a visitor can never hit a blank or browser-default page, everywhere at once.

4

Cohesion-by-construction: shared primitives + token tiers

Visual-system cohesionConfidence 85%Complexity Medium

The compounding bet. Extract <Eyebrow>, <PageHeader>, <RecipeGrid>, <EmptyState> so every index/card/header routes through one source; add a href() URL helper to kill the ~13 copies of the BASE_URL slash-strip; restructure @theme into three tiers (primitives → semantic aliases like --surface/--ink/--accent → component) and add the missing motion-token layer (--ease-*, --dur-fast/base/slow) so the header collapse, filter expand, FamilyMap draw, and card hovers move with one hand.

basis · direct: eyebrow styling across ~8 files, BASE_URL across ~13, .recipe-grid duplicated. external: Tailwind v4 best practice = 3-layer tokens; the motion layer is the most-skipped source of "unpolished" feel.

Why it matters: turns cohesion from a vigilance problem into a structural property — one edit to the grid or a semantic token reflows/recolors every page in sync. Underpins survivors #1–#3, #5. Best split into a small first slice (Eyebrow + PageHeader + href helper) before the token refactor.

5

Type-only OG cards + schema.org Recipe (build-time)

Identity & shareabilityConfidence 85%Complexity Medium

The site is deliberately photo-free — so make that the brand of the share card instead of the reason there isn't one. Generate a per-recipe og:image at build (title in Fraunces, terracotta-on-cream, spirit/glass icons, attribution credit line, on the dark-header field) via Astro endpoint + satori/resvg, and emit schema.org Recipe JSON-LD from the same ingredients[]/steps[]/garnish the page already renders. One <Meta> head component in BaseLayout; zero per-recipe asset work.

basis · direct: no og:image/ld+json in BaseLayout; frontmatter already rich enough to populate both. external: complete Recipe schema → measurable rich-result CTR lift.

Why it matters: every shared link is currently invisible word-of-mouth loss. A type-driven card is distinctive in a feed full of food photos and locks shares to the palette so they can never go off-identity.

6

A flavor descriptor on every card — make the grid scannable

Visual-system cohesionConfidence 78%Complexity Low–Med

Difford's proves a one-line tasting descriptor turns a grid from "list of names" into browsable authority. Give every RecipeCard a uniform sub-line — either authored, or derived deterministically from method + base spirit + top two flavors[] ("Stirred bourbon · bitter, citrus") as a guaranteed fallback so no card is ever bare. Lands the same unit on the home grid and all /by-* pages.

basis · external: Difford's per-card descriptor. direct: method/spirits[]/flavors[] present on every recipe; "empty states only on home" + inconsistent eyebrows are listed gaps.

Why it matters: an alphabetical grid of names forces click-to-evaluate; a descriptor lets the eye triage — what makes a reference site feel authoritative rather than thin. Decision to settle: derived vs authored (voice vs uniformity).

7

Recipe "make mode": spec plate + ingredient checkboxes + serving scaler

Recipe presentationConfidence 72%Complexity Medium

Make the detail page read like a cookbook and work like a tool. A fixed "spec plate" under the title (glass · method · ice · difficulty as iconed chips — the data-driven "hero" the no-photo direction actually wants); a register split between data sections (Ingredients/Steps) and prose (Notes); tappable ingredient checkboxes (highest-engagement recipe interaction, 80–90% mobile); and a servings stepper that scales parsed oz amounts. Small client islands over components that already exist.

basis · external: NYT Cooking register-split, SideChef checkboxes/mobile. direct: recipe/{Ingredients,Steps,HouseMade,BatchInstructions} already discrete; Icon.astro exists; glass/method/ice/difficulty populated but never used as a visual unit.

Why it matters: recipes are used at the bar, not just read — make-mode is where the site beats a printed cookbook. Scope first: the scaler needs an amount-parsing contract (½ oz, "2 dashes", "to top").

Bigger bets — scope before committing

Larger bet

A · Collapse the 7–8 /by-* pages into one parametric Browse template

Browse & discoveryConfidence 80%Complexity Medium

Eight near-identical [facet].astro files differ only by which field they filter. Derive them from one facets.ts config feeding a single TaxonomyIndex.astro — adding a browse dimension becomes a one-line entry, and every facet page gets identical header/empty-state/grid by construction. Reframe further: /by-spirit/gin is just the home grid pre-filtered (/?spirit=gin), so the two discovery systems could merge into one surface.

basis · direct: 7–8 sibling by-* dirs, ~1.3KB each, structurally identical; home already has a URL-param filter grid.
Larger bet

B · "What can I make?" cabinet lookup

Browse & discoveryConfidence 68%Complexity Medium

A client island where the visitor checks the spirits they own and sees fully-makeable recipes (plus "one bottle away"), computed from a build-time JSON of spirits[]. Difford's "Cabinet" pattern; the existing filter island proves the technique. Turns the collection from a catalog into a tool with zero new content — but it's arguably a feature beyond "polish," hence the scope flag.

basis · external: Difford's Cabinet reverse-lookup. direct: every recipe has validated spirits[]; index.astro filter island is the working precedent.
